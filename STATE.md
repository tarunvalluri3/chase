- **2026-08-17, Product decision (pre-Phase 6, docs only — no code changed):** Corrected the meaning of `MISSED`. It no longer means "the user never completed this task" — it means only "the deadline passed without the system receiving a completion confirmation." An overdue ACTIVE task auto-transitions to `MISSED` (unchanged mechanism from the original Phase 6 design: lazy check on read, plus an optional non-scheduled `sweepMissedTasks`), but MISSED is now a checkpoint the user must resolve, not a final verdict. Added `POST /api/tasks/:id/resolve-missed` (body `{ "resolution": "INCOMPLETE" | "COMPLETED" }`, authenticated + ownership-scoped, only callable on a MISSED task) as the resolution mechanism: `INCOMPLETE` keeps the task `MISSED` (terminal) and preserves the original `missed_reason`/`missed_at`; `COMPLETED` moves it to `COMPLETED`, sets `completed_at`, updates `updated_at`, and deliberately leaves `missed_at`/`missed_reason` un-cleared so the task's missed history survives the correction — no schema change needed for that, since those columns already exist and nothing required nulling them on a further transition. As part of this, **removed the manual `POST /api/tasks/:id/miss` endpoint from the design entirely** — under the corrected model, a user cannot self-declare a task "missed" (that would just be a same-effort path to DELETED with extra steps); MISSED is exclusively system-detected.
